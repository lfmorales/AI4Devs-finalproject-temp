## 18.6: una ejecución real contra la API de Equativ

### Antes

- Las dos variables, `EQUATIV_CLIENT_ID` y `EQUATIV_CLIENT_SECRET`, están rellenas en `.env`; se comprobó por su longitud, sin mostrar los valores.
- El contenedor del backend no las tenía, porque se había creado antes; se recreó con `docker compose up -d --force-recreate backend` y entonces las recibe. El del frontend no las recibe (no lee `.env`, a propósito). Los datos de desarrollo siguieron intactos tras el reinicio.
- Hora de inicio: 12:24 UTC, después de las 06:00 UTC, con la ventana por defecto.

### Cómo se ejecutó

Una sola vez: `run_ingestion --dsp Equativ` dentro del contenedor del backend, con la ventana por defecto, llamando a su propio `main(["--dsp", "Equativ"])` con el cliente que construye el propio comando. Un script de un solo uso, fuera del repositorio y pasado por la entrada estándar, envolvió ese cliente solo para contar las filas a su paso, porque las filas sin línea vinculada no guardan el gasto ni el curator en la base. El informe creado en Equativ no se borró.

## Comprobaciones con curl

### Cómo se hizo

- Un script local, fuera del repositorio, firma en memoria un token del emisor de pruebas por petición (RS256 con la clave privada de `.secrets/test-issuer/`, que no está en el repositorio), con la forma de los de Entra y el `oid` y el correo del usuario E2E del perfil. Los usuarios E2E se sembraron con la misma SQL que el *global setup* (`e2e/support/e2e-users.ts`).
- curl recibe la cabecera `Authorization` por su entrada estándar (`-K -`): ningún token se escribe en disco, en este informe ni en la lista de procesos.
- Este informe no reproduce cuerpos de petición ni de respuesta: de cada llamada guarda el método, la ruta (con el id de la línea sustituido por `{id}`), el perfil, el código HTTP esperado y el obtenido, y el código del cuerpo de los errores. Las comprobaciones sobre campos las hace el script sobre la respuesta y aquí solo consta el veredicto.
- Las campañas que se registran se llaman `STEP18-…`. Los paquetes probados son los valores inventados de la especificación.
- Orden: primero las lecturas y el cierre que funciona, con los datos de la demo; después las escrituras. No hay endpoint para borrar campañas: el `reset-data.sh` final deja la base como estaba.
