## Cómo se hizo

- **Tokens.** Un script local, fuera del repositorio, firma en memoria un token del emisor de pruebas por petición (RS256, con la clave privada de `.secrets/test-issuer/`, que no está en el repositorio). Cada token lleva el `oid` y el correo del usuario E2E del perfil. Los usuarios E2E se sembraron con la misma SQL que el *global setup* (`e2e/support/e2e-users.ts`). curl recibe la cabecera `Authorization` por su entrada estándar (`-K -`), así que ningún token llega al disco, a este informe ni a la lista de procesos.
- **Qué se registra.** De cada llamada: el método, la ruta, el perfil, el código HTTP esperado y el obtenido, y el código del cuerpo de los errores. Los identificadores numéricos de las rutas se escriben `{id}`. Las comprobaciones sobre los campos las hace el script sobre la respuesta, y aquí solo consta su veredicto.
- **Nombres de autor.** Los nombres que se comprueban («E2E finance», «E2E operations», «E2E trading») son los fijos de los usuarios E2E del emisor de pruebas. No son personas.
- **Ningún DSP real.** Ninguna tarea de este grupo pide una ejecución contra Adform o Equativ, y no se hizo ninguna. Las entregas son inventadas y van al DEMO DSP.
