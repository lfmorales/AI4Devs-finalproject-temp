## 12A. E2E Harness and First Specs

Playwright lives in `e2e/` at the repository root with its own `package.json` (`@playwright/test` as the only dependency, version pinned) and `package-lock.json`, Chromium only; nothing under `backend/` or `frontend/` changes. Real Cognito sign-in is not driven by the specs (it is covered only by `login.spec.ts`): the session is injected.

What is injected, read from `frontend/lib/auth/cognito-config.ts` and oidc-client-ts 3.5.0: the `UserManager` keeps its user in `sessionStorage` under the key `oidc.user:<authority>:<client_id>`, where the authority is `https://cognito-idp.<region>.amazonaws.com/<userPoolId>` and `client_id` is the app client. Both are the `iss` and `aud` claims of the Cognito ID token, so the key is built from the token and no `.env` is read by the specs. The stored value is the JSON of the oidc-client-ts `User`: `id_token` (the only field the application uses, as the bearer token), `access_token`, `token_type`, `scope` (`openid email`), `profile` (`sub`, `iss`, `aud`, `exp`, `iat` and `email`, taken from the token) and `expires_at` (the token's `exp`), so that `user.expired` is false. The injected `access_token` is the ID token itself, which is only valid as long as the application does not use the access token (today it reads `id_token` alone); if that changes, the injection must carry a real access token.
